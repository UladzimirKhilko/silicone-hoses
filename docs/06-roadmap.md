# 6. План разработки

Работаем итерациями: после каждого этапа — рабочая версия, которую вы смотрите и даёте замечания.
Сроки ориентировочные и зависят от того, как быстро будут образцы документов и ответы на вопросы.

| Этап | Что получаем | Срок |
|---|---|---|
| **0. Анализ** | Разбор всех образцов, ответы на вопросы, утверждённые модель данных и правила разнесения расходов | 1 нед. |
| **1. Каркас + справочники** | Проект, CI, база, вход и роли. Заводы, номенклатура, чертежи (загрузка пачкой, просмотр), импорт текущей номенклатуры из Excel | 1–2 нед. |
| **2. Поставки вручную** | PO, инвойсы, PL, поставки, приёмка, остатки (склад / в пути / заказано) — ввод через формы и вставку из Excel. **Уже можно работать.** | 2 нед. |
| **3. Автозагрузка документов** | Парсеры инвойсов и PL (CN + RU) по шаблонам ваших заводов, сопоставление с номенклатурой и синонимы, сверки инвойс ↔ PL ↔ приёмка | 2–3 нед. |
| **4. Расходы и себестоимость** | ТТН/CMR, расходы поставки, разнесение по базам, курсы НБРБ, себестоимость по партиям, отчёт по поставке | 1–2 нед. |
| **5. Заявки клиентов** | Загрузка заявки, «есть / будет / заказать», резервы, ответ клиенту, отгрузки | 2 нед. |
| **6. Помощник закупки** | Черновик заказа в Китай из дефицита + точки перезаказа, MOQ и кратность, экспорт в формате завода с чертежами | 1–2 нед. |
| **7. ИИ-распознавание** | Сканы/PDF/фото/китайский текст, свободные заявки клиентов | 1–2 нед. |
| **8. Запуск** | Сервер, домен, бэкапы, перенос остатков, обучение, неделя сопровождения | 1 нед. |
| **9. Развитие** | Отчёты/аналитика, 1С, Telegram-бот, ЖД-спецификация, сканер штрихкодов | по запросу |

**MVP (этапы 0–4)** — ~7–10 недель: учёт поставок, остатков и себестоимости с автозагрузкой документов.

## Как работаем

- Код — в этом репозитории, каждая задача — отдельная ветка и pull request с описанием.
- Каждый парсер покрывается тестами на реальных образцах из `samples/` — новый формат завода =
  новый образец + тест, старые форматы не ломаются.
- После каждого этапа — демо-стенд и короткий список «что сделано / что проверить».
- Требования и решения фиксируются в `docs/` (этот набор документов — живой).

## Риски

| Риск | Что делаем |
|---|---|
| Заводы меняют формат документов | профили шаблонов + ИИ-фолбэк + тест на каждый формат |
| Одно изделие — разные названия у заводов и клиентов | таблица синонимов, самообучение на ручных сопоставлениях |
| Нет единой номенклатуры сейчас | на этапе 0–1 вместе чистим и утверждаем справочник |
| Расходы приходят после продажи | пересчёт себестоимости партии с историей |
| Неясные правила учёта (курс, НДС, FIFO) | решения бухгалтера фиксируем в этапе 0 |
