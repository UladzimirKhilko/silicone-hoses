# 9. Как сервис различает изделия

> Исправление к первой версии разбора: я написал, что `BSI 90-60` и `BSI 90/60`, `D63,5` и `63.5` —
> «одно изделие с разным написанием» и что сервис будет «приводить названия к одному». **Это неверный и
> опасный подход.** Разбор всех 87 чертежей показал, что похожие названия очень часто означают **разные
> патрубки**, а одно и то же изделие в разных документах пишется так, что простая «нормализация»
> его либо не узнает, либо склеит с чужим.

## Главное правило

**Изделие = чертёж.** Уникальный ключ изделия — **обозначение ЯПИБ** (например, `ЯПИБ 24.1155`).
Код вида `BSI 90/60` — это наименование, а не идентификатор. Если чертежа нет (рукав 1 м) — ключ
задаётся вручную при заведении карточки.

Сервис **никогда не склеивает названия автоматически**. Каждое написание из документа
(инвойс, PL завода, маркировка на коробке, заявка) — это отдельный **синоним**, который один раз
подтверждает человек. Дальше этот синоним узнаётся автоматически.

## Почему нельзя «нормализовать»

### 1. Есть две разные системы обозначений, и они пересекаются

**Система А — параметрическая** (МТЗ, Гомсельмаш):
`BSI [угол-]D<диаметр>[/<диаметр2>]L<длина>[/<длина2>][-COR]-<исполнение>`

**Система Б — номинальная** (ММЗ): `BSI <угол>-<диаметр>[-<вариант>]`, где `/` — переход диаметров.

Одна и та же строка читается в двух системах по-разному:

| Строка | Как прочитать по системе А | Что это на самом деле (по чертежу) |
|---|---|---|
| `BSI 90-60` (инвойс) | угол 90°, Ø60 | **прямой переход Ø90→Ø60**, L148 (ЯПИБ 24.1155, на чертеже `BSI 90/60`) |
| `BSI 141-50-63.5` (инвойс) | ?, вариант «-63.5» | **угол 141°, переход Ø50→Ø63,5** (ЯПИБ 24.1156, на чертеже `BSI 141-50/63,5`) |
| `BSI D63,5` (инвойс) | Ø63,5 без длины | **прямой Ø63,5, L126** (ЯПИБ 24.1157, на чертеже `BSI 63,5`) |
| `BSI 80-38` | угол 80° или Ø80? | **угол 80°, Ø38** (ЯПИБ 24.1189) |

Вывод: в инвойсе `/` заменён на `-` (видимо, потому что `/` нельзя в имени файла),
и строка стала похожа на изделие другого типа. Правило «`/` = `-`» склеило бы разные изделия.

### 2. Суффиксы `-01…-04` в системе Б — это разные изделия

| Обозначение | Код | Плечи, мм | Особенность |
|---|---|---|---|
| ЯПИБ 24.1158 | BSI 90-63,5 | 95 × 70 | |
| ЯПИБ 24.1159 | BSI 90-63,5-01 | 182 × 96 | |
| ЯПИБ 24.1160 | BSI 90-63,5-02 | 93 × 93 | |
| ЯПИБ 24.1162 | BSI 90-38 | 132 × 58 | |
| ЯПИБ 24.1163 | BSI 90-38-01 | 70 × 70 | |
| ЯПИБ 24.1164 | BSI 90-38-02 | 113 × 80 | |
| ЯПИБ 24.1165 | BSI 90-38-03 | 107 × 61 | |
| ЯПИБ 24.1166 | BSI 90-38-04 | 113 × 86 | пространственный изгиб |

Все — угол 90°, но это **8 разных патрубков**. Отбросить «-01» = перепутать изделия.

### 3. Последняя цифра в системе А (`-1/-2/-3`) — исполнение по материалу, а не просто цвет

| Суффикс | Цвет | Температура / давление (по чертежам) |
|---|---|---|
| `-1` | чёрный | −50…+120 °C, 0,1 МПа (D54L80-1) |
| `-2` | синий | −50…+170 °C, 0,4 МПа (МТЗ); −60…+180 °C, 0,3 МПа (Гомсельмаш) |
| `-3` | красный / оранжевый | −50…+230 °C, 0,4 МПа (МТЗ); −60…+200 °C, 0,3 МПа (Гомсельмаш) |

`BSI D60L80-2` и `BSI D60L80-3` — одинаковая геометрия, **разный материал**, разные ЯПИБ (24.1113 и 24.1114).
Это разные изделия. Кроме того, у разных заказчиков один и тот же суффикс означает разные
характеристики — поэтому характеристики берём **из чертежа**, а не из кода.

### 4. Имя файла чертежа может не совпадать с самим чертежом

- Файл `BSI 45-D70L171_71-2.pdf`, а на чертеже — **`BSI 45-D70L171/71-3`**, цвет красный/оранжевый
  (ЯПИБ 25.1383). Имя файла ошибочное. **Истина — штамп чертежа.**
- Файлы ММЗ и МТЗ с `D` в имени (`BSI D63,5`) при штампе без `D` (`BSI 63,5`).

### 5. Один чертёж — несколько файлов

В папке Гомсельмаша «для согласования» лежат файлы `1.pdf…22.pdf`:
- `1–17` — побайтные копии именованных файлов;
- `18–22` — исходники из AutoCAD для гофр (COR), а именованные `BSI D76L160-COR-3.pdf` и т.д. —
  **сканы с подписями** «Согласовано для опытных образцов… НТЦК ОАО „Гомсельмаш“».

То есть у чертежа есть **версии и статусы** (исходник → согласован с подписями). В сервисе это
один чертёж с несколькими файлами, а не разные изделия.

## Как будет работать сопоставление

1. **Справочник изделий** заполняется из чертежей: ЯПИБ, код по штампу (с `/` и `,` как на чертеже),
   заказчик, тип, диаметры, длины, угол, исполнение, цвет, температура, давление, масса.
   Данные из штампа вводит/проверяет человек (текст в PDF нарисован линиями).
2. **Таблица синонимов**: `строка из документа → ЯПИБ`, с источником (инвойс RU, PL завода,
   маркировка коробки, заявка МТЗ…) и автором подтверждения.
3. При загрузке документа:
   - **точное совпадение** с синонимом или кодом по штампу → строка сопоставлена;
   - допустимые «безопасные» отличия: пробелы, приставка «Патрубок силиконовый», приставка `BSI`,
     **десятичная запятая/точка** (`63,5` = `63.5`) — только это;
   - всё остальное (`/`↔`-`, наличие `D`, отсутствие суффикса) — **только подсказка** с кандидатами,
     решение принимает человек;
   - подсказки ранжируются по разбору параметров + контексту документа (то же кол-во, та же
     смешанная коробка, тот же заказ Q…);
   - синоним, который указывает на два разных изделия, — **запрещён**, сервис покажет конфликт.
4. Подтверждённые синонимы копятся: со второй-третьей поставки почти всё узнаётся само.
