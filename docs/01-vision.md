# 1. Видение сервиса

## Проблема

Патрубки марки BSI заказываются на китайском заводе (пока один — Qinghe County Tushun Auto Parts) для заказчиков МТЗ, Гомсельмаш, ММЗ и др. По каждой поставке приходит пачка
документов на разных языках и в разных форматах: инвойс, упаковочный лист (китайский и
русский), ТТН/CMR, таможенные документы, счета перевозчиков. Нужно:

- понять, **что именно и сколько** пришло (по наименованиям, коробкам, весу);
- **сверить** инвойс ↔ упаковочный ↔ ТТН ↔ фактическую приёмку;
- **разнести расходы** (доставка, таможня, брокер, СВХ…) на каждое изделие и получить себестоимость;
- видеть **остатки** — на складе, в резерве, в пути;
- по **заявке клиента** быстро ответить, что есть, что будет, что нужно заказать;
- **сформировать заказ в Китай** на нужный завод в его формате;
- по любому изделию **открыть чертёж**.

Сейчас это, скорее всего, делается в Excel вручную — долго и с ошибками.

## Что делает сервис (функции)

| # | Функция | Суть |
|---|---|---|
| F1 | Справочник изделий | Номенклатура патрубков: размеры, тип, цвет, слойность, завод(ы), коды завода, чертёж (с версиями) |
| F2 | Чертежи | Хранение, просмотр в браузере (PDF/изображения), поиск изделия по параметрам и по чертежу |
| F3 | Заказы в Китай (PO) | Формирование заказа по заводу с учётом MOQ, кратности упаковки, экспорт в Excel/PDF в формате завода |
| F4 | Инвойсы | Загрузка (Excel/PDF/скан) → распознавание → сопоставление строк с номенклатурой → привязка к заказу |
| F5 | Упаковочные листы | Загрузка китайского и русского PL → коробки, места, вес нетто/брутто, объём, шт. в коробке по каждому наименованию |
| F6 | Поставки (партии) | Объединение инвойсов/PL/ТТН/расходов одной отправки; статусы: заказано → отгружено → в пути → на таможне → принято |
| F7 | ТТН и расходы | Загрузка ТТН/CMR, счетов перевозчика, таможенных платежей; разнесение расходов по строкам |
| F8 | Себестоимость | Landed cost по каждой позиции партии в BYN (и USD/CNY), с курсами НБРБ |
| F9 | Приёмка | Фактический приход на склад, акт расхождений (недостача/излишек/брак) |
| F10 | Остатки | Склад / резерв / свободно / в пути (с ETA) / заказано; по партиям |
| F11 | Заявки клиентов | Загрузка заявки (Excel/текст/фото) → сопоставление → «есть / будет / заказать» → резерв |
| F12 | Отгрузки клиентам | Списание со склада, история продаж (если учёт продаж не ведётся в 1С) |
| F13 | Помощник закупки | Подсказка, что и сколько заказать: дефицит по заявкам + точка перезаказа + MOQ |
| F14 | Сверки и контроль | Автопроверки расхождений между документами, предупреждения |
| F15 | Отчёты | Остатки, движение, себестоимость, оборачиваемость, ABC, поставки в пути |
| F16 | Пользователи и роли | Админ, закупщик, кладовщик, менеджер продаж, бухгалтер (только чтение/экспорт) |

Возможные расширения позже: Telegram-бот («есть ли патрубок 76/63 угол 90?»), интеграция с 1С,
выгрузка ЖД-спецификации для таможни (у вас уже есть навык `zhd-specifikatsiya` — переиспользуем логику),
мобильная приёмка со сканером штрихкодов.

## Как я вижу решение

**Веб-приложение** (открывается в браузере, работает и с телефона) с базой данных PostgreSQL.

Ключевая идея — **«документ → черновик → проверка человеком → проводка»**:

1. Пользователь загружает файл (инвойс, PL, ТТН) как есть.
2. Сервис сам распознаёт его: Excel — программно по шаблону завода; PDF/скан/китайский текст — через
   ИИ-распознавание (Claude API) с выдачей структурированной таблицы.
3. Строки автоматически сопоставляются с номенклатурой (по коду завода, размерам, синонимам).
4. Пользователь видит черновик с подсвеченными сомнительными местами, правит, подтверждает.
5. Только подтверждённый документ попадает в учёт. Исправления запоминаются (новые синонимы) —
   с каждой поставкой распознавание точнее.

Всё, что приходит, сверяется между собой: инвойс ↔ PL по количеству, PL ↔ ТТН по весу и местам,
PL ↔ приёмка по факту. Расхождения — в отдельный список на разбор.

## Чего сервис НЕ делает (на старте)

- Не ведёт бухгалтерский учёт и не заменяет 1С (только экспорт/интеграция).
- Не подаёт таможенную декларацию.
- Не общается с заводами автоматически (формирует документ, отправляете вы).
